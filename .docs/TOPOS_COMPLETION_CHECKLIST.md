# TOPOS 0.1.0 completion checklist

This is an acceptance ledger for the current TOPOS completion work, not a release certificate. It covers each of the 50 requirements in the [canonical SRS](CoChem-TOPOS_SRS.md), the supplied [full method matrix](../wiki/Method_Matrix.md), its [constraint mapping](method_matrix.md), and the [source-qualified historical proposals](TOPOS_0.1.0_RECOMMENDATIONS.md). A test that rejects an unsupported calculation establishes honest failure handling; it does not complete that calculation capability.

The user has specified a mandatory **CoChem-BASE + CoChem-TOPOS + CoChem-TORQ** installation. TOPOS owns its workflow, contracts, scientific validation, review, and handoff. BASE owns the deployed ORCA/GitHub Actions execution service. TORQ owns the downstream torsion/kinetic implementation. A working BASE ORCA calculation is evidence about BASE; TOPOS acceptance additionally requires the exact TOPOS request, operation, method, input identity, remote job, returned quantities, and artifacts to remain correlated. Completing TOPOS does not certify the unfinished TORQ scientific solver.

## How to read the ledger

- **Implementation/evidence** identifies the relevant code and focused acceptance tests. The [330-test local receipt](TOPOS_OPEN_SOURCE_VALIDATION.json) remains a historical baseline; later components and final-tree verification are separate evidence.
- **Open** means a concrete acceptance obligation remains. An adapter or numerical utility by itself does not close an end-to-end workflow requirement.
- **Conditional** means the SRS explicitly makes the capability conditional, or its scientific rule applies when that capability is requested. Such a capability must be absent from supported choices until its prerequisites are met. Conditional is not a synonym for implemented.
- **Verification pending** means the completion pass must supply current, reviewable evidence before changing the status. The final receipt must identify the source hashes, command, interpreter, required engines, outcomes, and limitations.

The [current validation receipt](TOPOS_COMPLETION_VALIDATION.json) records **907 passed, zero failures/errors/skips**, with **238.19 s process wall time**, on Python 3.12.14. Genuine xTB 6.7.1, CREST 3.0.2 and installed BASE were required. The checked production/test source inventory remained unchanged throughout verification. Ruff, dependency consistency, actionlint for all five workflows, source/wheel builds, wheel import and diff checks passed. Isolated numerical tests explicitly selected the development runner; BASE integration tests exercised installed authority and the real broker. These results do not establish live hosted ORCA execution or complete matrix coverage.

The SRS permits a published, bounded chemistry/engine/platform capability profile. It does not permit relabeling a missing requested engine or a different Hamiltonian as success. Matrix inventory coverage, executable row coverage, and experimentally supported accuracy are three separate measurements.

The supplied document covers substantially more than TOPOS conformer search: Tables 1–10 include PES/DVR, geometry, vibrational averaging, binding, secondary observables, large-amplitude motion and other spectroscopy. Enumerating those rows with applicability/status is required for truthful routing; it does not assign all TORQ/CFOUR/engine-internal algorithms to TOPOS.
