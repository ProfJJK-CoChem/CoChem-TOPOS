# **CoChem-TOPOS 3.0 Implementation Guide**

**Document Purpose:** This guide details the exact operational boundaries, data schemas, and script-by-script handoff mechanisms required to successfully execute or interface with the CoChem-TOPOS v3.0 topographical search and Method Matrix cascade pipeline.

## **1\. Operational Execution Boundaries**

Before executing any TOPOS module, maintainers must adhere to the following ecosystem constraints:

### **1.1 The Registry Mandate**

CoChem-TOPOS is strictly "headless" regarding environment parameters. It will **never** guess where a binary (like ORCA or MACE) is located, nor will it assume available RAM.

* **Requirement:** Every execution must successfully load $HOME/CoChem\_Artifacts/cochem\_system\_config.json.  
* **Enforcement:** If this JSON is missing or structurally invalid (failing the Pydantic schema check), the pipeline will immediately throw a SystemExit to prevent unconstrained subprocesses from hard-crashing the host OS.

### **1.2 The Filesystem Air-Gap**

To guarantee that Git repositories remain clean and that users do not inadvertently push 50GB wavefunction files to public servers, TOPOS strictly obeys the air-gap.

* **Execution Tier:** Python logic runs from $HOME/CoChem-TOPOS/.  
* **Artifact Tier:** All scratch files (.gbw, .tmp), .xyz trajectories, and .h5 databases are forced into $HOME/CoChem\_Artifacts/.

### **1.3 IPC & Subprocess Brokerage**

TOPOS **does not** use os.system() or subprocess.run() directly for heavy calculations.

* All MACE-OFF23 and ORCA 6.1.1 calls are packaged as dictionary payloads and handed to cochem\_core.subprocess\_broker.SubprocessBroker.  
* This ensures proper OpenMPI thread binding, Core-Dump sweeping, and Zombie Process reaping if a calculation hangs.

## **2\. Script-by-Script Data Handoffs**

The TOPOS workflow is segmented into distinct execution batches. Understanding the input/output boundaries of each script is critical for debugging or extending the pipeline.

### **Phase 1: Ingestion & Topology**

**core\_engine/01\_INGEST\_GC.py**

* **Trigger:** Invoked via the Master Integrator or via webhook from CoChem-UNITY.  
* **Input:** Raw .xyz, .mol, or SMILES strings from user upload.  
* **Action:** Executes the Fast-Pass optimization (EMT/UFF) to normalize bond lengths. Evaluates Graph Connectivity (GC) using NetworkX to map the initial adjacency matrix.  
* **Handoff:** Passes a sanitized, zero-indexed Cartesian array string to the GOAT array.

### **Phase 2: Exploration & Deduplication**

**core\_engine/cochem\_topos\_crusher.py**

* **Trigger:** Receives the raw, messy ensemble of conformers generated by the MACE-OFF23 or GOAT structural searches.  
* **Input:** Thousands of .xyz snapshots of local minima.  
* **Action:** 1\. Fast Sieve: NetworkX connectivity hashing (purges broken bonds).  
  2\. Structural Sieve: Coulomb Matrix Eigenspectrum variance.  
  3\. Refinement Sieve: Kabsch SVD RMSD alignment with Chiral Volume protection (prevents enantiomer collapse).  
  4\. *The Jiggle-Quench:* Pushes boundary conformers 25% toward each other and re-optimizes. If they collapse into the same basin, one is deleted.  
* **Handoff:** Writes strictly unique, Eckart-aligned isomers to a temporary SQLite cache.

**core\_engine/cochem\_topos\_escape.py**

* **Trigger:** Automatically invoked by The Crusher if a targeted topological basin yields zero viable conformers.  
* **Action:** Applies progressive Langevin thermal auto-tuning (300K \-\> 500K \-\> 1000K) to force the molecule over high energetic barriers.  
* **Handoff:** Returns discovered high-energy coordinate vectors back to the Crusher.

### **Phase 3: The Method Matrix Cascade**

**cascade\_engine/cochem\_topos\_cascade\_orchestrator.py**

* **Trigger:** Instantiated by cochem\_topos\_master.py.  
* **Input:** Unique, baseline isomers from Phase 2\.  
* **Action:** Polls cochem\_topos\_cascade\_matrix.py for the rules engine. Routes the molecule through escalating levels of theory (Tier 1: MACE ![][image1] Tier 2: r2SCAN-3c ![][image1] Tier 3: wB97X-D4 ![][image1] Tier 4: DLPNO-CCSD(T)). Intercepts multireference failures (T1 \> 0.02) and dynamically injects Counterpoise corrections for complexes.  
* **Handoff:** Returns the finalized analytical Hessian, gradient matrices, and exact electronic energies.

### **Phase 4: SWMR Persistence & Telemetry**

**cascade\_engine/cochem\_cascade\_hdf5.py**

* **Trigger:** Called by the Orchestrator after every successful tier completion.  
* **Input:** Multi-tier geometries and heavy tensor arrays (Hessians).  
* **Action:** Opens landscape.h5 in libver='latest' and swmr=True modes. Serializes the massive tensors using lzf compression chunking.  
* **Handoff:** Forces an OS-level h5py.File.flush(). This is the critical handoff point where downstream visualizers (CoChem-DOCK) instantly pick up the data for live browser rendering without file-lock collisions.

### **Phase 5: FAIR Export & Publication**

**export\_utils/cochem\_topos\_export.py**

* **Trigger:** Called at the absolute conclusion of the Master pipeline.  
* **Input:** The finalized landscape.h5 database.  
* **Action:** Scrapes the terminal tier data. Uses Jinja2 string interpolation to generate a strictly formatted, siunitx-compliant LaTeX document (TOPOS\_Supporting\_Information.tex).  
* **Handoff:** Bundles the .h5, .tex, and a JSON provenance manifest into TOPOS\_FAIR\_Archive.zip deposited in the Artifacts directory, ready for journal SI or Zenodo.

## **3\. Interfacing with Downstream Modules**

CoChem-TOPOS is designed to feed cleanly into property-prediction modules.

* **CoChem-TORQ (Rotational Spectroscopy):** TORQ does not need to re-optimize TOPOS structures. It simply mounts landscape.h5 in Read-Only SWMR mode, extracts the Tier 4 geometries, and immediately begins calculating Principal Axes of Inertia and dipole moment tensors.  
* **CoChem-SPYCF (Vibrational Spectroscopy):** Mounts landscape.h5 to extract the analytical Hessians stored by the Cascade engine, enabling instant VPT2 anharmonic corrections.

## **4\. Diagnostics & Recovery**

If the Master Integrator (cochem\_topos\_master.py) crashes:

1. **Do not delete landscape.h5:** The SWMR persistence guarantees that all progress up to the exact moment of the crash is preserved.  
2. **Check cochem\_system\_config.json:** Ensure that the RAM allocations were not exceeded by the Subprocess Broker, leading to an OS-level OOM kill.  
3. **Resume:** Simply restart the Master script. It is designed to read the .h5 file, identify the last completed geometry, and resume the Method Matrix cascade seamlessly.
